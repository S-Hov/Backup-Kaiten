# Пользователи и локальный доступ

Профиль из Kaiten (`users`) и локальный вход (`accounts`) разделены.
Импорт не создаёт паролей, сессий и активных аккаунтов. Права и маски Kaiten
сохраняются в `users.source_data`, но не превращаются в права локальной системы.

## Что уже работает

- `/login` — вход по почте и локальному паролю, выход через меню аккаунта.
- `/activate#token=…` — одноразовая установка/сброс пароля, ссылка на 24 часа.
- `/users` — администратор видит импортированные профили, выдаёт доступ,
  получает новую ссылку установки пароля, меняет роли, отключает аккаунты.
- `/profile` — свой профиль, активные входы, смена пароля и выход со всех устройств.
- `/login` и `/activate` доступны только гостям: перед показом проверяется
  сессия. Уже вошедший пользователь перенаправляется на доску; свой пароль он
  меняет в профиле. Ошибка проверки сессии показывает повтор запроса, а не форму.
- Участник читает и изменяет доски; наблюдатель только читает; администратор
  дополнительно управляет доступом. Роли действуют на все текущие доски.
  Пространства и ограничения доступа к отдельным доскам пока не включены.

Нельзя отключить или понизить последнего активного администратора. Отключение
аннулирует сессии и приглашения. Отключение ожидающего приглашения также
отменяет ссылку; выдача новой ссылки позволяет пригласить его заново.
Смена роли применяется на сервере при следующем запросе.

Ссылку установки пароля передаёт администратор: SMTP и самостоятельная
регистрация не настроены. После принятия ссылки пользователь входит отдельно.
Токен берётся из текущего fragment адреса. Его изменение без перезагрузки
создаёт новое состояние формы и удаляет прежний черновик/результат. Несколько
параметров `token` в одной ссылке не допускаются. Сервер проверяет хеш всего
полученного токена; изменённый токен не меняет пароль, сессии или приглашение.
Смена/сброс пароля завершает все предыдущие сессии этого аккаунта.
Новые карточки, комментарии, вложения и история перемещений получают реального
локального автора, связанного с исходным профилем пользователя.

## Первый администратор и восстановление доступа

Команда не принимает пароль и не выводит его. Она использует существующий профиль
с указанной почтой; если профиля нет, создаётся локальный. Несколько профилей с
одинаковой почтой требуют ручного разрешения неоднозначности, без их слияния.

```powershell
docker compose run --rm --no-deps tools invite-user --email your-email@example.com --role admin --base-url http://127.0.0.1:8766
```

Откройте напечатанную ссылку и задайте пароль самостоятельно. Для администратора
с потерянным паролем выполняется та же команда. Новая ссылка отменяет предыдущую.
Не сохраняйте ссылки в Git: до истечения срока они дают возможность задать пароль.

## Таблицы

| Таблица | Назначение |
| --- | --- |
| `users` | Импортированный профиль и собственный UUID: имя, почта, username, статус Kaiten, initials, timezone, language, avatar_url, полный source_data |
| `accounts` | Один локальный аккаунт на профиль: уникальная нормализованная почта, хеш пароля, роль, active, даты входа/смены пароля/отключения |
| `login_sessions` | Отзываемые сессии на 12 часов, хеши случайных session/CSRF-токенов, срок и user-agent |
| `access_tokens` | Хеши одноразовых приглашений/сбросов, срок и отметка использования |
| `auth_throttles` | Счётчики ограничений попыток, ключи в виде хешей |
| `auth_events` | Входы, неудачи входа, выходы, выдача доступа, смены пароля и прав; без паролей и токенов |
| `source_records` | Снимок, тип сущности, её UUID, относительный путь исходного JSON и указатель записи внутри массива |

Миграция `0004_local_auth` добавляет колонки профилей/аккаунтов и новые таблицы.
Ни миграция, ни открытие страницы не запускают экспорт или импорт карточек.
Существующие `roles` и `space_memberships` остаются заготовкой прав пространств;
локальная общая роль сейчас хранится в `accounts.role`.

## Защита и настройки

Пароли хешируются scrypt (`N=2^17`, `r=8`, `p=1`, случайная соль 16 байт).
Длина пароля 12–128 символов. Одновременно выполняется не более двух затратных
операций хеширования на процесс. Выбор параметров опирается на
[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Случайный токен сессии хранится в HttpOnly-cookie, его хеш — в БД. В localStorage
нет пароля или токена входа. Cookie имеет SameSite=Strict. Изменения требуют
CSRF-заголовка, связанного с текущей сессией; Origin проверяется по разрешённому
списку. Подход к сессиям: [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
Ошибки входа не раскрывают, существует ли аккаунт. Ограничения: 10 попыток на
почту и 30 на клиентский адрес за 15 минут; установка пароля — 30 на адрес.

API досок, архивов, исходных JSON-представлений и вложений закрыт авторизацией,
включая старые пути `/api` и `/assets`. Публичны оболочка сайта, статика,
health/ready, вход и установка пароля. Просроченные/отозванные сессии сервер не
принимает независимо от состояния браузера. Физическая очистка старых строк
сессий и журнала пока не автоматизирована.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `BOARD_SECURE_COOKIES` | `0` | Для локального HTTP; при размещении за HTTPS установить `1` |
| `BOARD_ALLOWED_ORIGINS` | localhost/127.0.0.1:8766 и :5173 | Разрешённые Origin для изменений, через запятую |

Разрешение дополнительных хостов и HTTPS относится к настройке локального
сервера. Авторизация обязательна в обычном запуске; `auth_required=False`
используется только явно в изолированных тестах прежних API.


## Аватарки пользователей

Аватарки показываются в меню аккаунта, на карточках доски, в участниках и комментариях, в архиве и справочнике пользователей. Если изображения нет или файл недоступен, отображаются инициалы.

В «Профиль и безопасность» пользователь может загрузить свою картинку, вернуть импортированную из Kaiten или выбрать инициалы. Допускаются PNG, JPEG, WebP и GIF до 5 МБ и 16 мегапикселей. Сервер проверяет содержимое, учитывает ориентацию фотографии и сохраняет квадратный PNG 256×256 без исходных метаданных; у GIF используется первый кадр.

Таблица `user_avatars` связывает локальный UUID пользователя с импортированным и личным `file_objects`, а также хранит выбранный режим. Сами файлы находятся в постоянном томе `uploads`; включайте его в резервную копию вместе с PostgreSQL. Исходные данные пользователя не изменяются. Повторный импорт не сбрасывает личный выбор.

После миграции `0005_user_avatars` сохранённые в БД данные профилей можно обработать отдельно, без импорта карточек:

```powershell
docker compose run --rm --no-deps tools import-avatars
```

Команда извлекает встроенные PNG с инициалами и скачивает фотографии по сохранённым ссылкам `https://files.kaiten.ru`. Другие хосты и перенаправления запрещены. Недоступная фотография заменяется сохранённым изображением с инициалами; число замен выводится в отчёте. Повторный запуск пропускает уже сохранённые файлы; `--force` обновляет импортированный вариант. При недоступности фотографии следующий запуск повторит попытку получить её. Браузер получает изображения только с локального сервера.

API: `POST /api/v1/auth/avatar` принимает бинарное содержимое файла, `POST /api/v1/auth/avatar/reset` — JSON `{"mode":"imported"}` или `{"mode":"initials"}`. Обе операции используют текущую сессию и CSRF-защиту; изменить чужую аватарку через них нельзя. `GET /api/v1/users/{user_id}/avatar?v={file_id}` доступен после входа. Версия в URL меняется при замене файла. После изменения клиент обновляет данные профиля и карточек без выхода из аккаунта.
