# Запуск через Docker Compose

Из корня проекта, при запущенном Docker Desktop с Linux containers:

```powershell
python scripts/setup_docker.py
docker compose up --build -d
docker compose ps
```

Приложение: <http://127.0.0.1:8766>. Порт можно изменить через `BOARD_WEB_PORT`
в `.env` или окружении. По умолчанию он отличается от порта локального `viewer.py`.
Локальный Python нужен только для
однократного создания файла пароля; зависимости приложения устанавливаются в образ.
При следующих запусках достаточно `docker compose up -d`.

## Что запускается

| Сервис | Назначение |
| --- | --- |
| `db` | PostgreSQL 18; данные в постоянном томе `postgres_data` |
| `migrate` | Применяет Alembic-миграции после готовности PostgreSQL, затем завершается |
| `web` | FastAPI и существующий клиент; начинает работу после успешной миграции |
| `tools` | Разовые команды импорта; запускается по запросу |
| `backup` | Существующий экспортёр Kaiten; запускается по запросу |

PostgreSQL не публикует порт на компьютере. Веб-порт доступен на localhost.
Контейнер приложения работает под отдельным непривилегированным пользователем.
Образ не содержит архив, API-токен, `.env` или локальные настройки.

Пароль PostgreSQL хранится в `.secrets/postgres_password` и передаётся контейнерам
через Compose secret. Скрипт подготовки не перезаписывает существующий пароль.
Каталог исключён из Git. Сохраните этот файл при переносе вместе с данными БД:
пересоздание файла не меняет пароль уже инициализированной базы.

Для PostgreSQL 18 том подключён к `/var/lib/postgresql`, согласно
[инструкции официального образа](https://hub.docker.com/_/postgres).
Порядок старта основан на [проверках готовности Compose](https://docs.docker.com/compose/how-tos/startup-order/).

## Перенос существующего архива в PostgreSQL

По умолчанию интерфейс читает полный JSON-архив (`BOARD_STORAGE=archive`), а PostgreSQL
готов для следующего этапа. При первом запуске новая база пуста. Список доступных
снимков — имена папок в `backups/`.

```powershell
# Для проверки можно ограничиться одной карточкой.
docker compose run --rm tools import-archive --snapshot "2026-10-22_08-58-24_447787Z_board_437516" --card-id 14796440

# Весь снимок; повторный запуск обновляет записи без дублирования.
docker compose run --rm tools import-archive --snapshot "2026-10-22_08-58-24_447787Z_board_437516"

# После полного импорта переключить интерфейс на SQL-хранилище.
$env:BOARD_STORAGE = "database"
docker compose up -d web
```

Импорт сохраняет все JSON-разделы и справочники в существующие архивные SQL-таблицы.
Это ещё не рабочая модель редактируемой доски из [предложения схемы](DATABASE_DESIGN.md).
Исходные файлы не меняются. Вложения остаются в `backups/`: веб-приложение
и импортёр подключают каталог для чтения. Не удаляйте его после импорта.
Состояние `partial` исходного экспорта сохраняется: импорт не исправляет отсутствующие
в исходной копии данные. Ошибки чтения отдельных карточек выводятся в результате;
при таких ошибках команда завершается с кодом 2.

Вернуться к полному JSON-архиву: задайте `$env:BOARD_STORAGE = "archive"`
и выполните `docker compose up -d web`. Частичный проверочный импорт в SQL
не означает переноса всей доски. На этапе настройки проверен импорт 800 реальных
карточек; этот SQL-снимок помечен `limited`.

На Windows чтение сотен тысяч мелких файлов через bind mount может быть медленным.
Для большого архива есть ускоренный вариант:

```powershell
python scripts/import_docker_archive.py --snapshot "2026-10-22_08-58-24_447787Z_board_437516"
```

Скрипт упаковывает только JSON, передаёт их во временный контейнер и запускает тот
же импортёр внутри Docker. PostgreSQL и формат записей те же. Вложения не копируются.
Временные файлы и контейнер удаляются по завершении; во время переноса потребуется
дополнительное свободное место под JSON-архив и его распакованную копию.

## Экспорт из Kaiten в контейнере

Используются существующие `config.toml` и `.env` в корне проекта.
Пути назначения в конфиге должны быть относительными к `/app`, например `backups`,
а не Windows-путями. Этот сервис имеет запись в `backups/`.

```powershell
docker compose run --rm backup --all --plan
docker compose run --rm backup --all
```

Экспорт не импортирует результат в PostgreSQL автоматически. Периодическое обновление
и webhooks пока не включены, см. [SYNCHRONIZATION.md](SYNCHRONIZATION.md).

## Проверка и обслуживание

```powershell
docker compose ps
docker compose logs --tail 80 web migrate
docker compose logs --tail 80 db
docker compose down
```

`down` останавливает контейнеры, сохраняя том базы. После изменения кода:
`docker compose up --build -d`. Версии Python-зависимостей закреплены
в `requirements-runtime.lock`. `/api/v1/health` проверяет процесс,
`/api/v1/ready` также проверяет выбранное хранилище (в режиме database — SQL-таблицы).

Постоянный том обеспечивает сохранность при пересоздании контейнера, но отдельная
резервная копия PostgreSQL и вложений всё равно нужна. Её регламент будет отдельной
задачей после утверждения рабочей схемы. Для доступа с локального сервера позднее
добавим домен, HTTPS, авторизацию и настройки разрешённых хостов.
