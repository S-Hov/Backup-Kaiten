# Клиент React + TypeScript + SCSS

Целевая архитектура для развития сложной доски и сравнение с `auto-admin`:
[FRONTEND_ARCHITECTURE.md](FRONTEND_ARCHITECTURE.md). Ниже описан текущий код;
переход на FSD выполнен для доски и архивного просмотрщика.

Стек: React, TypeScript в строгом режиме, Vite, SCSS, TanStack Query для запросов
и кеша. Сервер и API остаются на FastAPI. Это клиентское приложение для внутренней
доски: серверный рендеринг и отдельный Node-сервер сейчас не нужны.
[React описывает Vite как вариант сборки отдельного клиента](https://react.dev/learn/build-a-react-app-from-scratch).

## Запуск

Обычный запуск — `docker compose up --build -d` из корня проекта.
Docker сам устанавливает зависимости по `package-lock.json`, собирает клиент и
копирует результат в Python-образ. Приложение доступно на <http://127.0.0.1:8766>.
Node работает только на этапе сборки и не нужен в запущенном Python-контейнере.

Для разработки с быстрым обновлением клиента нужен Node.js 24:

```powershell
# Из корня проекта; API должен работать на 8766.
npm --prefix frontend ci
npm --prefix frontend run dev
```

Откройте <http://127.0.0.1:5173>. Vite проксирует `/api` и `/assets` в FastAPI,
поэтому отдельные CORS-разрешения и второй API-адрес в компонентах не нужны.
Если порт сервера изменён, поправьте адрес прокси в `frontend/vite.config.ts`.

Сборка для обычного `viewer.py`:

```powershell
npm --prefix frontend run build
```

FastAPI отдаёт только `frontend/dist/index.html` и файлы `dist/static/`.
Исходники TS/SCSS, настройки и `node_modules` не публикуются. Путь `/assets`
сохранён за вложениями, поэтому Vite использует `/static` для JS/CSS.
Если клиент ещё не собран, корневая страница отвечает 503 с инструкцией сборки.

## Разделение кода

```text
frontend/src/
  app/                         маршруты, провайдеры и общие SCSS
  pages/board/                 главная страница, выбор и обновление доски
  pages/archive/               просмотрщик резервных копий (ленивая загрузка)
  widgets/kanban-board/        колонки, подколонки и дорожки
  widgets/card-inspector/      карточка, обсуждение, вложения, безопасный текст
  entities/board/              схемы, запросы, ключи кеша и дерево колонок
  entities/archive/            схемы и запросы исторических карточек
  shared/api/                  HTTP-клиент, ошибки и отмена запросов
  shared/ui/                   общие компоненты и иконки
  shared/lib/format/           даты и размеры
  test/                        вымышленные данные и настройки тестов
```

Компонент карточки не делает запросов. Переходы к связанным карточкам передаются
через callback. Поэтому подключение новых рабочих таблиц позднее не потребует
заново писать отображение. В неизвестных разделах сохраняется тип JSON, без `any`.

TanStack Query разделяет кеш по снимку, номеру карточки и поисковому запросу,
отменяет устаревшие запросы и управляет загрузкой/ошибками/пагинацией.
Адрес содержит `snapshot`, `card` и `q`; прямые ссылки и кнопки назад/вперёд работают.
React Router разделяет главную доску `/` и архив `/archive`. Выбор рабочей доски
сохраняется в `?board=UUID`. При входе запрашиваются только список досок и структура
выбранной доски, без карточек. Старые ссылки архива с корневого пути сохраняются.

Общий HTTP-клиент проверяет ответы Zod-схемами, различает HTTP-ошибки, нарушение
контракта и отмену. Дополнительные поля ответа сохраняются. Схемы и запросы
относятся к сущности, а транспорт не зависит от предметной области.
Импорты идут вниз по слоям; доступ к чужому модулю — через публичный `index.ts`.
Проверка архитектуры на AST отслеживает нарушения и циклы импортов в CI.

HTML из архива очищает DOMPurify, Markdown разбирает marked. Скрипты, обработчики
событий и встроенные стили удаляются. Картинки показываются из локальных вложений
по карте сервера или разрешённых растровых data URL. Внешние недоступные изображения
заменяются понятной подписью. CSP сервера остаётся включённой.

## Проверки

```powershell
npm --prefix frontend run check:architecture
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

Vitest и React Testing Library проверяют отображение сохранённых разделов, связи,
недоступные вложения, неизвестные JSON-поля, поиск, смену снимка при незавершённом
запросе и очистку опасного HTML. CI отдельно собирает и проверяет клиент.

Главная доска читает структуру рабочих SQL-таблиц; архив показывает существующие копии. Перетаскивание, редактирование,
создание карточек и вход пользователей ещё не включены; это следующие операции
над согласованной рабочей моделью БД. Новый импорт не запускается при открытии сайта.
