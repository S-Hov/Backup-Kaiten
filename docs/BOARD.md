# Главная доска

Главная страница `/` показывает структуру рабочей доски из PostgreSQL
(локально также поддерживается SQLite). Архивный просмотрщик находится в `/archive`.
Прежние ссылки `/?snapshot=...&card=...` перенаправляются туда с сохранением параметров.

При открытии клиент запрашивает `GET /api/v1/boards`, затем
`GET /api/v1/boards/{uuid}/structure`. Выбор доски хранится в параметре `board`
адресной строки. TanStack Query кеширует ответы и повторяет устаревшие запросы.

Ответ структуры содержит `board`, `columns`, `lanes`. Для колонок передаются
`id`, `title`, `parentId`, `sortOrder`, `type`, `wipLimit`; для дорожек —
`id`, `title`, `sortOrder`. Рабочие ID — UUID; исходный ID Kaiten — строка
`board.sourceId`. Порядок задаёт сервер по точному десятичному значению,
в JSON `sortOrder` передаётся строкой без потери точности в JavaScript.

Исторические заглушки (`is_stub`) не включаются. Поддерживаются вложенные
колонки, дорожки и отображение положительного WIP-лимита. Если дорожек нет,
клиент рисует одну основную. Циклические связи колонок выводят сообщение об ошибке.
Нет данных, загрузка и ошибка запроса имеют отдельные состояния.

После получения структуры каждая ячейка «колонка × дорожка» запрашивает
`GET /api/v1/boards/{uuid}/cards?column_id=UUID&lane_id=UUID&limit=30`.
Если дорожек нет, `lane_id` опускается и выбираются карточки без дорожки.
Ответ: `items` и `nextCursor`. «Показать ещё» запрашивает следующую порцию
с `cursor`. Сервер сортирует по точному `sort_order`, затем UUID;
архивные, удалённые карточки и заглушки исключены. Данные карточек берутся из
рабочих SQL-таблиц, JSON-файлы для этого не читаются.

Превью содержит UUID, номер (строка), заголовок, положение, точный порядок
(строка), версию, срочность, теги и обложку. Описания, история и исходный JSON
не попадают в список. Теги и обложки выбираются пакетно для всей порции.
Числовые цвета тегов соответствуют стабильным ячейкам нашей палитры в
`_tokens.scss`; это собственная палитра, точное совпадение оттенков с Kaiten
не заявляется. Для отсутствующего или неизвестного цвета применяется
стабильный выбор по ID/значению, без случайной смены цвета при перерисовке.

Обложка: доступное растровое изображение с `card_cover=true`, иначе первое
доступное изображение самой карточки по порядку и UUID. Изображения комментариев
и пользовательских полей не используются как запасная обложка. Удалённые,
невыгруженные и нерастровые файлы исключены. Флаг `cover.explicit` сообщает,
была ли обложка назначена явно. Несуществующий локальный файл даёт 404;
клиент показывает подпись и сохраняет название/теги. Файл выдаётся через
`/api/v1/attachments/{uuid}/image` по ключу из БД с проверкой границ хранилища.
Сейчас изображения загружаются лениво в оригинальном размере; отдельные
миниатюры — дальнейшая оптимизация.

Переиспользуемый `entities/card/BoardCard` получает объект `card` и необязательный
`onOpen`, сам не делает API-запросов. Догрузкой управляет виджет доски.
При ошибке догрузки первая порция остаётся видимой. Sonner показывает сообщения
ошибок запросов и будущих операций через общий QueryProvider.

Перетаскивание, редактирование параметров и живые события пока не включены.
Перемещение в следующую колонку доступно кнопкой в окне карточки.
Схема будущих событий описана в [REALTIME.md](REALTIME.md).
По нажатию карточка открывается в модальном окне. Детали, файлы и навигация —
[CARD_DETAILS.md](CARD_DETAILS.md).
Открытие сайта не запускает импорт JSON и не обращается к Kaiten.

## Панель доски

«Доски» сохраняет общую вертикальную прокрутку. «Списки» выделяет каждой
конечной колонке собственную вертикальную прокрутку; дорожки находятся внутри
этой колонки. Горизонтальная прокрутка общая. Переключение вида использует
тот же кеш карточек и не требует повторного запроса свежих данных.
Режим хранится в `localStorage` под ключом `board-view`; явный `view` в URL
имеет приоритет. При недоступном хранилище переключение продолжает работать.

Рядом с названием колонки показано количество карточек с учётом всех фильтров.
API страницы возвращает `total` до применения курсора и лимита. Доска суммирует
значения по дорожкам, а для родительской колонки — по конечным подколонкам.

Поиск в шапке передаёт `q` в API с задержкой 350 мс или сразу по Enter.
Сервер ищет подстроку без учёта регистра в названии, номере и названиях тегов.
Знаки `%` и `_` трактуются буквально. Поиск применяется ко всем карточкам
выбранной доски, а не только к загруженной порции.

«Архив» добавляет `archived=true` в запрос карточек и показывает архивные
карточки рабочей доски. Удалённые карточки и заглушки остаются исключёнными.
«Архив копий» в боковом меню ведёт к прежнему просмотрщику снимков `/archive`.
Архивация и восстановление карточек пока не реализованы.

Клик по метке на превью включает фильтр по её UUID, повторный клик снимает
его. Можно выбрать несколько меток: карточка должна содержать все выбранные
метки. Эти условия объединяются с текстовым поиском и состоянием архива.
API принимает повторяющийся параметр `tag_id=UUID&tag_id=UUID`; фильтрация
выполняется в БД до пагинации. Название метки в URL служит только подписью.

Клик по аватарке участника аналогично переключает фильтр пользователя.
Повторяющийся параметр `user_id` выбирает карточки со всеми указанными участниками.

Кнопка «Дата» позволяет выбрать дату создания, обновления или срок выполнения
и диапазон «С»/«По». Можно заполнить только одну границу. API принимает
`date_field=created|updated|due`, `date_from` и `date_to` в формате `YYYY-MM-DD`.
Границы включают оба дня целиком; `timezone_offset` передаёт смещение браузера
в минутах по соглашению `Date.getTimezoneOffset()`. Для создания и обновления
используется дата источника, при её отсутствии — локальная дата записи.
Карточки без срока не попадают в диапазон по сроку выполнения.

Под панелью управления отображаются активные фильтры. Каждый можно убрать
кнопкой с крестиком. «Очистить» справа сбрасывает метки, пользователей, даты, текст и архив,
сохраняя выбранную доску и вид «Доски»/«Списки».

В правом углу шапки — текущий аккаунт, меню профиля и выхода. Администратору доступен список пользователей. Цвета панели и формы
используют общие переменные темы; светлая тема остаётся темой по умолчанию.
Пути страниц и параметры описаны в [ROUTING.md](ROUTING.md).

## Редактирование карточки

Название, описание и значения полей редактируются на месте: нажмите на значение,
измените его и выберите «Сохранить» или «Отмена» под этим полем. Общей кнопки
редактирования и отдельной формы нет. Доступны срок с временем, приоритет, тип,
колонка и дорожка, размер, плановые даты, дата завершения, внешний ID и обычные
дополнительные поля. Пункт чек-листа можно отметить или изменить его текст.
Системные даты, версия, создатель и исходные данные остаются справочной информацией.

У тегов, участников и подписчиков есть поиск, добавление и крестик удаления.
Выбор сохраняется целиком кнопкой под соответствующим блоком. Поиск включает
доступные значения из локального каталога, включая ещё не назначенные карточкам.
Новый тег создаётся из строки поиска; участнику можно назначить роль ответственного.
Дополнительное поле добавляется через поиск «Добавить поле».

Одновременно открыто одно поле. Escape отменяет его редактирование, Ctrl+Enter
сохраняет текстовое поле. Закрытие карточки с черновиком запрашивает отказ от
изменений. Во время записи действия заблокированы; ошибка оставляет черновик.
Наблюдателям и архивным карточкам редактирование недоступно.

`POST /api/v1/cards/{uuid}/edit` принимает `version` и изменённые поля `title`,
`description`, `dueDate`, `asap`, `tagIds`, `members`, `subscriberIds`, `typeId`,
`sizeText`, `size`, `sizeUnit`, `externalId`, `plannedStart`, `plannedEnd`,
`completedAt`, `properties`, `checklistItems`. Пропущенные поля не меняются; `dueDate: null`
очищает срок, `description: ""` очищает описание. Название — 1–500 символов после
обрезки пробелов, описание — до 100 000 символов, дата — ISO 8601 с часовым поясом.
Сервер проверяет версию под блокировкой строки. Устаревшая версия даёт 409,
не перезаписывая актуальные данные. Изменение увеличивает версию и добавляет
событие «Карточка изменена» со списком полей. Исходные данные Kaiten не меняются,
запросов во внешнюю доску нет. Изменения хранятся в локальной БД.

`GET /api/v1/boards/{uuid}/edit-options` возвращает локальные каталоги тегов,
пользователей, типов и дополнительных полей с вариантами выбора.
`POST /api/v1/boards/{uuid}/tags` принимает `name` и `requestId`, возвращает тег.
Повтор запроса и создание тега с уже существующим названием не дают дубликат.

## Перетаскивание карточек

В видах «Доски» и «Списки» активную карточку можно перетащить в другую
конечную колонку или дорожку, а также изменить её порядок внутри ячейки.
Рамка выделяет целевую ячейку, линия «Вставить сюда» показывает точное место.
Положение сохраняется в локальной БД; при ошибке карточка остаётся на месте.
Для архива и роли «Наблюдатель» перетаскивание отключено.

`POST /api/v1/cards/{uuid}/move` принимает `version`, `columnId`, `laneId`
и необязательный `beforeCardId` либо `afterCardId`. Без соседа карточка
добавляется в конец ячейки. Сосед разрешается по полному списку, поэтому
фильтры и постраничная загрузка не меняют смысл выбранного места вставки.
Сортировка остаётся `sort_order, id`; дробная позиция рассчитывается сервером
без округления в JavaScript. При одинаковых позициях или исчерпании точности
сервер перенумеровывает целевую ячейку с сохранением порядка. Изменённые
карточки получают новую версию; устаревшая версия или исчезнувший сосед дают 409.
Перенос между ячейками записывается в историю, перестановка внутри ячейки — нет.

## Создание локальной карточки

«Добавить» открывает форму с названием, колонкой и дорожкой. Клиент вызывает
`POST /api/v1/boards/{uuid}/cards` с `title`, `columnId`, `laneId` и `requestId`
(UUID одной попытки создания). Название после обрезки пробелов — 1–500 символов.
Сервер проверяет принадлежность колонки и дорожки доске, запрещает создание
в колонке с подколонками и ставит карточку в конец активной ячейки.

Ответ 201 содержит `{id}`. Повтор с тем же `requestId` и данными возвращает
ту же карточку; повтор с другими данными даёт 400. Клиент сохраняет этот ID
при ручном повторе запроса, автоматические повторы записи отключены.
После успеха кеш доски обновляется, фильтры поиска/архива сбрасываются и
открываются детали новой карточки. Ошибка оставляет форму и введённый текст.

Запись создаётся только в локальной БД, без запроса в Kaiten. Исходные
`source_id`, `source_instance_id` и номер Kaiten остаются пустыми. Файлы,
теги, описание и участники через эту начальную форму пока не назначаются.
