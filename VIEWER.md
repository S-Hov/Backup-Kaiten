# Просмотр карточек из резервной копии

## Запуск

```powershell
cd C:\work\backups\doska_kaiten
.\.venv\Scripts\python.exe viewer.py
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Для остановки нажмите
Ctrl+C в окне PowerShell. Python 3.11+. Сначала установите зависимости по инструкции README.md.

Можно указать другой каталог с копиями или другой порт:

```powershell
.\.venv\Scripts\python.exe viewer.py --backup-root "D:\Копии Kaiten" --port 8766
```

`--backup-root` указывает на общий каталог, внутри которого находятся папки
снимков вида `2026-10-22_..._board_437516`. В каждом снимке должна быть папка `cards`.

## Как пользоваться

- Выберите резервную копию слева.
- Введите номер карточки, например `14796378`, и нажмите Enter.
- Для поиска по названию введите фрагмент названия и нажмите Enter; выберите
  заказ в результатах слева. Список загружается порциями по 40 записей.
- Основная часть показывает название, положение на доске, тип, участников,
  ответственного (звёздочка), срок, метки, пользовательские поля, описание,
  чек-листы, файлы и связи.
- В правой части переключайте комментарии, перемещения, события и исходные JSON.
  Для больших лент есть кнопка «Показать ещё».
- Картинки можно увеличить нажатием. Закрыть увеличенное изображение можно
  крестиком или Esc. Вложения скачиваются по стрелке у имени.
- В «Дополнительных сведениях» доступны даты, учёт времени, блокировки,
  итерации, базовые планы, SLA (если был сохранён).
- «Все поля карточки» показывает каждое поле `card.json`, в том числе технические.
  Вкладка JSON содержит **все прочитанные JSON-файлы папки**, включая неизвестные
  просмотрщику новые разделы и отдельные чек-листы.
- «Скачать данные» сохраняет объединённый объект карточки в один JSON. Это
  данные и метаданные; сами бинарные вложения скачиваются отдельно. Адреса
  вложений в этом объекте ведут на локальный просмотрщик.
- Адрес открытой карточки можно скопировать. Такая ссылка открывается на этом
  компьютере при запущенном просмотрщике.

Оформление повторяет основные приёмы карточки Kaiten: белая форма, строки
полей с серыми подписями, фиолетовые акценты, участники, метки и боковая лента.
Это самостоятельный локальный просмотрщик, а не точная копия клиентского кода
Kaiten. В этой версии карточки открываются для чтения.

Ошибки копирования показываются в карточке; отсутствующий файл не заменяется
обманчивым изображением. Отсутствующий раздел отличается от успешно
сохранённого пустого списка. Просмотрщик не исправляет исходные ошибки выгрузки.
Он читает архив и не изменяет его файлы. После изменения/дозагрузки копии
перезапустите просмотрщик: справочники и список карточек кэшируются в памяти.

## Архитектура для перехода на БД

```text
Папка архива → ArchiveRepository / SqlCardRepository → CardService → normalize_card → CardViewModel v1
                                                        ↓
                                                 <kaiten-card>
```

- `backend/app/infrastructure/archive/repository.py` — адаптер хранения. По номеру открывает папку и
  читает все `*.json` внутри неё. Интерфейс `Repository` описывает операции
  списка копий, поиска, получения карточки и справочников.
- `backend/app/presentation/card_model.py` — нормализация в единый объект `schemaVersion: 1`.
  Сопоставляет ID со справочниками и ссылки картинок с локальными файлами.
- `backend/app/api/routes.py` — HTTP-адаптер и выдача вложений.
- `frontend/card-component.js` — компонент `KaitenCard`.
  Он **не делает запросов** и не знает о папках или базе данных.
- `frontend/app.js` — поиск, выбор копии, запросы и навигация.
- `frontend/rich-text.js` — безопасное отображение разметки.

Использование компонента:

```javascript
import '/card-component.js';
const element = document.createElement('kaiten-card');
element.data = cardViewModel; // объект CardViewModel v1
document.querySelector('main').replaceChildren(element);
```

Основные поля контракта:

```text
schemaVersion: 1
card:          основные сведения карточки
sections:      комментарии, участники, поля, чек-листы, история, события и др.
sectionStatus: available / empty / missing для ключевых разделов
files:         имена, размеры, статусы, локальные URL вложений
imageMap:      исходный URL картинки → локальный URL
raw:           содержимое всех исходных JSON, по именам файлов
diagnostics:   проблемы чтения и ошибки из отчёта резервной копии
source:        копия, число JSON, список сохранённых разделов
```

События компонента: `open-card` с `{id}` для перехода к связанной карточке и
`download-card` с `{data}` для выгрузки объединённого объекта.

При переходе на БД выберите `BOARD_STORAGE=database` после импорта архива,
сохранив HTTP-ответ `CardViewModel v1`. Компонент и большая часть интерфейса
останутся прежними. Полнотекстовый поиск и редактирование можно добавлять
отдельно; текущая реализация поиска использует сохранённые списки карточек и ID
папок и не перечитывает 20 тысяч подробных карточек на каждый запрос.

## Локальная работа и проверки

Сервер слушает только `127.0.0.1`, не читает `.env` и не обращается к Kaiten.
Статические файлы выдаются по явному списку; вложения — по сохранённому
манифесту с проверкой пути. HTML описаний очищается от активного содержимого.
Встроенные картинки загружаются только из архива; внешние обычные ссылки
открываются отдельно по нажатию. Поддержан Range для больших медиафайлов.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют чтение всех JSON, расшифровку справочников, поиск, повреждённые
разделы, пути вложений, выдачу файлов, Range и закрытые служебные пути.
