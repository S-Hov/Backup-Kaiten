# Резервная копия доски Kaiten

Python 3.11 или новее. Внешние библиотеки не требуются. Скрипт выполняет только
GET-запросы: сохраняет информацию из Kaiten на диск. Загрузки обратно в Kaiten
(восстановления) в этой версии нет. Здесь «экспорт/выгрузка» означает направление
Kaiten → локальная папка.

## Первоначальная настройка

Откройте PowerShell в `C:\work\backups\doska_kaiten`.

В `config.toml` заполните:

- `kaiten.board_url` — ссылку на ваш Kaiten; по ней определяется домен компании.
- `kaiten.board_id` — числовой ID конкретной доски. Если URL содержит
  `/boards/123`, его можно определить автоматически при `board_id = 0`.
  Ссылка `/space/123/boards` содержит ID пространства, а не доски: тогда
  `board_id` необходимо указать явно.
- В `.env` замените `PASTE_TOKEN_HERE` своим API-токеном. Переменная окружения
  `KAITEN_API_TOKEN`, если установлена, имеет приоритет над `.env`.

`config.example.toml` и `.env.example` — шаблоны. Рабочие файлы `config.toml` и
`.env` уже подготовлены с пустыми значениями. Не отправляйте `.env` другим людям.
Токен не записывается в копию, отчёт или вывод программы. Отправляется только
на домен из `board_url`; при перенаправлении HTTP авторизация снимается.

Пути внутри конфига вычисляются относительно файла конфига. По умолчанию копии
попадают в `backups/ДАТА_UTC_board_ID`, каждый запуск — отдельная папка.

## Команды

```powershell
cd C:\work\backups\doska_kaiten

# Каталог доступных функций; не требует конфига и сети.
python backup.py --list-functions

# Если есть только ссылка /space/123/boards, узнать ID досок через API.
# Нужен заполненный токен в .env; board_id пока может быть равен 0.
python backup.py --list-boards

# Проверить конфиг и показать состав выгрузки. Сеть и токен не нужны.
python backup.py --all --plan

# Пробная полная выгрузка трёх карточек.
python backup.py --all --limit-cards 3

# Вся доска: активные и архивные карточки, файлы, структура и справочники.
python backup.py --all

# Если SLA API отвечает HTTP 402, явно исключить эту функцию.
# Это новый состав копии; для него начинайте новый запуск без --resume.
python backup.py --all --exclude sla

# Полные карточки со связанными данными, без отдельной выгрузки структуры доски.
python backup.py --full-cards

# Выборочные функции можно комбинировать.
python backup.py --columns --lanes --users
python backup.py --cards --comments --history --activity
python backup.py --full-cards --card-id 12345 --card-id 12346
python backup.py --all --active-only

# Выгружать также связанных родителей, детей и блокирующие карточки
# с других досок, доступные владельцу токена. Есть защита от циклов.
python backup.py --all --follow-related

# Продолжить прерванную копию: повторить исходные флаги.
# Частоту запросов, таймауты и токен при этом можно поменять в конфиге.
python backup.py --all --resume "backups\ПАПКА_КОПИИ"

# Локальная проверка SHA-256 для сохранённых JSON и скачанных файлов.
python backup.py --verify "backups\ПАПКА_КОПИИ"

# Альтернативный конфиг.
python backup.py --config "config.toml" --all
```

В примере с `--resume` замените `ПАПКА_КОПИИ` реальным названием. При пробном
запуске с ограничением повторите также `--limit-cards 3`.
Чтобы получить новый снимок после завершения предыдущего, запустите без
`--resume`: продолжение предназначено для той же копии, а не для обновления
данных до текущего состояния.

`--card-id` выбирает конкретные карточки вместо перечисления доски. Доступная
карточка может находиться на другой доске; это явное ограничение области,
отмеченное в отчёте. `--limit-cards` ограничивает число выгружаемых карточек,
но сначала скрипт получает полный список карточек доски.

## Что означают флаги

| Флаг | Содержимое |
| --- | --- |
| `--cards` | Подробный JSON каждой карточки: описание, значения полей, встроенные данные и метаданные файлов; без скачивания файлов |
| `--members` | Участники каждой карточки |
| `--users` | Справочник доступных пользователей, включая неактивных; это не список всех пользователей безусловно |
| `--columns` | Колонки и подколонки |
| `--lanes` | Активные и архивные дорожки |
| `--board` | Настройки доски |
| `--comments` | Комментарии со всех страниц API |
| `--checklists` | Детальные чек-листы с пунктами |
| `--fields` | Определения пользовательских полей, варианты select и catalog |
| `--types`, `--tags` | Типы карточек и метки |
| `--history` | История перемещений карточек |
| `--activity` | Доступная лента событий компании с фильтром по карточке; нужны права на ленту компании |
| `--files` | Скачивание обычных и защищённых вложений, картинок из описаний и комментариев; автоматически включает `--comments` и `--fields` |
| `--children`, `--links`, `--blockers` | Дочерние карточки, внешние ссылки, блокировки |
| `--time-logs`, `--sla`, `--baselines` | Учёт времени, показатели SLA, доступные базовые планы |
| `--iterations` | История участия в итерациях, API beta |
| `--full-cards` | Все функции карточек выше плюс справочники полей, типов и меток |
| `--all` | `--full-cards` плюс все функции уровня доски |

Любая функция карточки получает её подробный JSON как обязательную основу.
`--full-cards` означает весь **поддержанный этой версией каталог**, доступный
через API владельцу токена. Он не обещает копию внутренних таблиц Kaiten.

По умолчанию связанные карточки других досок остаются как ID/связи; для их
рекурсивной выгрузки включите `--follow-related`. Связи, которые не были
выгружены, перечислены в `related_card_ids_not_exported` отчёта.

В полном режиме сохраняются доступные поля компании, варианты, типы и метки,
а не только применённые на выбранной доске. Часть API-методов имеет ограничения
по тарифу и правам. Ответ 403/404/402 записывается как проблема, а не считается
успешным сохранением пустого раздела. Отсутствующие права могут привести к
статусу `partial` даже при успешно скачанном основном содержимом заказов.

## Производительность

Настройки находятся в секции `[performance]`:

- `requests_per_second` — общий предел частоты всех запросов; по умолчанию 3.
- `min_interval_seconds` — дополнительный нижний предел интервала. Используется
  больший из него и `1 / requests_per_second`, поэтому настройки не конфликтуют.
- `page_size` — число записей на странице, от 1 до 100.
- `timeout_seconds` — таймаут сетевой операции, а не всего запуска.
- `retries` — число повторов после первоначальной попытки.
- `backoff_seconds`, `max_backoff_seconds` — задержки повторов. Ответы 429 и
  временные ошибки сервера повторяются с учётом Retry-After/RateLimit-Reset.
  Если сервер требует более долгую паузу, следующий запрос дождётся её окончания.

Работа последовательная: отдельного числа параллельных потоков нет. Это
упрощает контроль нагрузки и продолжение после сбоев. Начните с 3 запросов/с;
увеличивать частоту стоит после проверки на вашем аккаунте.

## Структура результата

```text
backups/ДАТА_board_ID/
  index.html                 Открыть в браузере
  report.json                Статус, объём, проблемы, границы выгрузки
  state.json                 Контрольные суммы и завершённые операции
  board/                     Структура, списки карточек и справочники
  cards/12345/
    index.html               Текст и локальные изображения заказа
    card.json                Подробные данные карточки
    comments.json            Комментарии
    activity.json            Доступная лента событий
    history.json             История перемещений
    ...                      Другие выбранные разделы
    files.json               Результаты скачивания и контрольные суммы
    files/                   Сами изображения и документы
```

Исходный текст сохраняется в JSON без преобразования разметки. HTML-просмотр
показывает безопасно экранированный текст, дополнительные разделы и изображения
из локальных файлов. Это простой просмотр архива; оформление редактора Kaiten
не воспроизводится. JSON и бинарные файлы — основная резервная копия.
Временные подписанные URL защищённых файлов удаляются из сохраняемых данных:
они истекают и не являются заменой самих файлов.

Статусы отчёта:

- `complete_for_selected_scope` — выбранные функции отработали без обнаруженных
  ошибок; это не гарантия наличия всех когда-либо существовавших данных.
- `limited` — намеренно установлен `--limit-cards`.
- `partial` — есть недоступные разделы, внешние вложения или ошибки.
- `running`, `interrupted`, `failed` — запуск не завершён.

Код выхода: 0 — выбранная область сохранена без ошибок (включая осознанный
пробный лимит); 2 — неполная копия или ошибки проверки; 1 — ошибка запуска;
130 — остановка Ctrl+C. Проверка `--verify` подтверждает целостность сохранённых
данных, но не их полноту на стороне Kaiten и не проверяет оформление HTML.

## Ограничения, которые важно учитывать

- Экспорт не атомарный: за время обхода сотрудники могут менять карточки.
  Для первой контрольной копии лучше выбрать период минимальной активности.
  Постраничный список и сохранённые разделы при `--resume` повторно не обновляются,
  если их контрольные суммы верны. Незавершённый раздел запрашивается заново.
- Скрипт видит только данные и историю, доступные токену. Полную историю всех
  предыдущих версий текста, удалённые файлы и уже недоступные карточки не обещает.
  Baselines API возвращает только доступные неархивные базовые планы.
- Из Google Drive, Dropbox и других внешних хранилищ сохраняется ссылка и
  проблема в отчёте. Сам файл нужно копировать через соответствующее хранилище.
- Картинки из текста скачиваются с домена компании и `*.kaiten.ru`. Для внешних
  источников укажите точные хосты в `extra_asset_hosts`. Произвольные обычные
  веб-ссылки и содержимое сайтов не скачиваются. Защищённый файл скачивается
  по временному адресу, полученному непосредственно из API, без bearer-токена.
- Сложные каталоги полей и связанные документы сохраняются в том объёме,
  который возвращают используемые методы; отдельного обхода документов,
  каталогов-баз данных компании, автоматизаций, прав доступа и настроек всей
  компании в этой версии нет.
- Восстановление в Kaiten — отдельная будущая задача. Эту копию можно читать
  независимо от сервиса; восстановление авторов, исходных дат и истории 1:1
  не подтверждено.

## Расширение проекта

- `kaiten_backup/catalog.py` — каталог методов API и состав групп флагов.
- `client.py` — GET, пагинация, ограничения частоты, повторы, перенаправления.
- `exporter.py` — отдельные операции, зависимости и отчёт.
- `files.py` — обнаружение и скачивание файлов.
- `storage.py` — атомарное сохранение и проверяемое продолжение.
- `config.py` — проверка настроек и локальное чтение токена.
- `backup.py` — флаги и точка запуска.

Добавление метода карточки в каталог автоматически добавляет флаг запуска
и включает его в `--full-cards`. Для нестандартной пагинации/зависимостей нужно
добавить обработчик в исполнителе, а не притворяться обычным списком.

Проверки без токена:

```powershell
python -m unittest discover -s tests -v
```
